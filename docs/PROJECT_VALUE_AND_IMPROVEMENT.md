## 一、AI 解读"暂时不可用"根因分析

### 1.1 触发路径定位

用户反馈近期出现 "⚠️ AI 解读暂时不可用（超时/服务忙），以下为系统自动生成的脱水数据摘要"。

代码定位（`src/briefing.py`）：
- 兜底函数：`_build_fallback_insight()` L575-626，文案在 L606
- 触发条件：**三层 LLM 降级链全部失败**才会走到这里

降级链结构（`_ai_insight()` L629-820）：

| 层 | 模型 | 客户端超时 | 失败后动作 |
|----|------|-----------|-----------|
| 1 主 | `deepseek-ai/DeepSeek-V4-Flash` | 120s | → 降级层 |
| 2 降级 | `Qwen/Qwen3.6-27B` | 90s | → 应急层 |
| 3 应急 | `Qwen/Qwen3.5-9B` | 30s | → 兜底纯文本 |

4 个直接触发点：
- `client is None`（API key 未配置）→ 标准模式直接兜底（L744-745）
- 主模型 `except`（L755）→ 降级层
- 降级模型 `except`（L786）→ 应急层
- 应急模型 `except`（L817）→ 兜底（L820）

### 1.2 头号根因：代金券只覆盖 9B，前两层付费导致欠费中断 🔴

**根因已由用户实测确认（2026-08-25），不是模型 ID 问题。**

`src/llm.py` 三个模型 ID **均真实存在**，但 SiliconFlow 代金券的免费覆盖范围与模型付费状态错配：

| llm.py 模型 ID | 真实性 | 代金券覆盖 | 失败后果 |
|--------------------|------|-----------|---------|
| `deepseek-ai/DeepSeek-V4-Flash`（主，120s） | ✅ 真实 | ❌ 需付费 | 欠费时直接 401/限流，走 except 降级 |
| `Qwen/Qwen3.6-27B`（降级，90s） | ✅ 真实 | ❌ 需付费 | 同上，第二层也挂 |
| `Qwen/Qwen3.5-9B`（应急，30s） | ✅ 真实 | ✅ 代金券免费 | 唯一能撑住的层，但质量有限 |

**失败链路**：账户微量欠费 → 前两层（付费）同时 401/限流 → 三层降级链只剩第三层 9B 兜底 → 9B 质量有限，遇到稍复杂 prompt 就返回过短（<10 字）或空内容 → 触发 `len(content) >= 10` 静默失败 → 最终走纯文本兜底 → 用户看到"AI 解读暂时不可用"。

**为什么是"偶尔"不是"一直"**：账户欠费是渐进的，代金券额度耗尽前 DeepSeek/Qwen27B 还能用；耗尽后才开始间歇性失败；深度欠费后两层全挂，只剩 9B 撑。

> ⚠️ 上一轮基于 WebSearch 结果武断判定模型 ID 无效，已被用户纠正。**对 API 模型列表/付费状态类问题，应以平台控制台实测为准，搜索结果可能滞后或不全**。

### 1.3 放大根因的代码设计缺陷

| 缺陷 | 位置 | 后果 |
|------|------|------|
| **异常信息被截断到 80 字符** | briefing.py L667/L690/L714/L758/L787/L818 的 `str(e)[:80]` | 排查时看不到完整错误（如 `model_not_found` 详情被截掉），只 log warning 不 log error |
| **返回过短被静默丢弃** | L663/L685/L752/L781/L813 的 `if len(content) >= 10` | 模型返回空 content（限流时常见，HTTP 200 但 body 空）会被当作失败，但只 log warning，用户看不到原因 |
| **`_build_portfolio_summary` 不传 client** | briefing.py L167 `pf = load_portfolio()` | 飞书 API 抖动 → 持仓数据变"持仓数据暂不可用" → LLM 收到无意义上下文 → 返回过短 → 触发 len<10 失败 → 连锁进降级链 |
| **无运行日志本地可查** | logs/ 目录不存在 | 失败原因只能在 GitHub Actions 云端看，本地无法复现 |

## 二、系统实际价值重估

### 2.1 核心矛盾：机械参考 vs 智能参考

用户反馈："投资助手不可能越俎代庖帮我去买/卖，目前只是拿它当参考，但参考作用还可以更高，感觉太机械了。"

这句话点出了真正的定位：**系统不需要变成"决策助手"（自动执行不现实也不合规），而要从"机械参考"升级为"智能参考"**。

| 维度 | 机械参考（当前） | 智能参考（用户期望） |
|------|-----------------|---------------------|
| 核心交付 | 7 时段固定结构铺陈全部数据 | 突出"今天和昨天比有什么变化" |
| AI 解读 | 每次从头翻译新闻+安抚 | 叙事化讲变化、讲因果、讲关联 |
| 信号展示 | 阈值触发就报，不管市场状态 | 语境化：结合 VIX/趋势/冷却期讲"为什么" |
| 用户感受 | 每天看一样的结构，容易疲劳 | 每条都有信息增量，值得看 |
| 衡量指标 | 推送到达率 | "这条参考是否帮我看到了原本会漏掉的东西" |

**当前系统的真实价值**：
- ✅ **有价值但不致命**：7 时段简报确实省了打开 5-6 个 App 的时间，板块轮动温差、纳指期货盘前风向是真实增量信息
- ⚠️ **价值天花板低**：AI 解读本质是"翻译新闻+安抚情绪"，每天结构一样，用户看完仍要自己判断，决策疲劳没减少
- 🔴 **"太机械"的根源**：`strategy.judge()` 已经算出有语境的硬信号（含趋势/冷却/雷达联动），但展示时被拍平成"🔴 强烈买入"这种无语境文字，AI 解读又与之脱节

### 2.2 已有但未释放的判断价值

`strategy.py` 的 `judge()` 函数已经具备智能参考的内核，但被当作"仓位健康报告"机械展示：

| 已算出的硬信号 | 当前展示方式 | 语境信息（被丢弃） |
|---------------|------------|------------------|
| `TRIGGER_STRONG_BUY`（偏离<-10%） | "🔴 强烈买入" 一行 | 趋势是否右侧、冷却期是否过、雷达是否同步 |
| `_check_cooldown`（3 天冷却） | 挂在 override 字段 | 何时到期、还差几天 |
| `_apply_left_side_intercept`（防飞刀） | "🛑 左侧下跌拦截" | 拦截何时可能解除、当前跌势斜率 |
| 时机闸门 | timing_msg 字段 | 左侧/右侧各几只、企稳确认度 |
| 雷达联动 | "🔭雷达同步" | 哪些标的同步、信号强度 |

**这些语境信息是 Python 死算的硬数据，比 LLM 解读可靠，但当前没有以"有语境的参考"形式呈现给用户。**

### 2.3 为什么"太机械"——五个具体表现

1. **定时推送疲劳**：7 时段固定推送，不管市场有没有变化都推同样结构。平淡日子里用户看一样的"VIX→市场→新闻→持仓→AI解读"，信息增量低
2. **AI 解读模板化**：六段式 prompt + 思维链固定，每次让 LLM 从头分析"大环境→逐大类→交叉→结论"，而不是讲"今天和昨天比有什么不一样"
3. **阈值不考虑市场状态**：±5%/±10% 死阈值，VIX 高位和低位用同一标准，左侧下跌和右侧企稳用同一阈值，机械触发
4. **全量铺陈不聚焦**：每次列全部持仓、全部板块、全部新闻，没变化的也占篇幅，真正该看的变化被淹没
5. **AI 与硬信号脱节**：`_ai_insight` 的 prompt 是"翻译新闻+安抚"，没把 `judge()` 的硬信号作为约束注入。LLM 可能在建议"关注美股机会"的同时，strategy 算出"美股已超配+冷却期未过"——两者矛盾，用户无所适从

## 三、改进方向：让建议更有参考价值

### 3.1 P0 —— 修复 AI 解读（见第一章，立即可做）

降级链调整（让免费层更厚或主模型选便宜付费）+ 日志加固，恢复基础可用性。这是后续所有改进的前提。

### 3.2 P1 —— 变化感知：从"定时全量铺陈"到"今日变化聚焦"（去机械感核心）

**问题**：当前 7 时段每次都铺陈 VIX→市场→新闻→财报→宏观→雷达→国际→持仓→AI 解读全量结构，平淡日子信息增量低，用户产生疲劳。

**改进方向**：
1. **简报开头加"今日变化摘要"**：3-5 行，只列今天和昨天比有变化的事——偏离度变化最大的大类、雷达新信号、VIX 跳变、板块温差异常、新闻中和持仓最相关的。数据全部来自现有模块，零新数据源。
2. **平淡日折叠**：如果今天各维度变化都在阈值内（如偏离度变化 <1pp、无新雷达信号、VIX 波动 <2），简报主体折叠，只推"今日变化摘要 + 一句话 AI 点评"，减少噪音。
3. **事件触发推送**（可选，进阶）：在定时简报之外，当出现"偏离度突破阈值""雷达新信号""VIX 单日跳变 >3"等事件时，主动推一条轻量提醒。当前 CI 只有定时，需加事件检测逻辑。

**实现要点**：需要在 briefing.py 增加一个"昨日快照"对比维度——把上次的偏离度/雷达信号/VIX 缓存（飞书「观测记录表」当前预留未用，正好落盘），下次简报对比差异。这是 D10 回测的数据基础，一举两得。

### 3.3 P1 —— 叙事化解读：AI 解读从"模板翻译"到"讲今天不一样的事"（去机械感核心）

**问题**：当前 `_ai_insight` 的 prompt 是"把当天财经新闻与真实持仓对照，给出有洞察力的解读"——这是信息整理任务，且每次让 LLM 从头分析"大环境→逐大类→交叉→结论"，结构固定，机械感强。

**改进方向**：把 AI 解读的 prompt 从"全面分析"改为"变化叙事"：

```python
# briefing.py _ai_insight prompt 改造（伪代码）
# 注入"昨日 vs 今日"对比数据
delta_block = "\n".join(
    f"- {s['asset_class']}: 偏离 {yesterday[s.cls]} → {today[s.cls]} "
    f"({'收窄' if abs(today)<abs(yesterday) else '扩大'} {delta}pp)"
    for s in verdict['signals']
)

prompt = build_analysis_prompt(
    role="你是量化投资顾问。今天和昨天相比，持仓偏离度有以下变化，"
        "请用大白话讲清楚：① 哪个变化最值得关注 ② 为什么变（结合新闻/趋势）"
        "③ 对用户持仓意味着什么。不要从头分析全部，聚焦变化。",
    holdings_text=pf_summary,
    market_text=market_text,
    extra_rules="""
    - 开头第一句就讲"今天和昨天比最大的变化是X"，不要套话
    - 只讲有变化的，没变化的大类一句话带过或不提
    - 结合硬信号讲因果："美股偏离收窄是因为纳指期货盘前涨0.5%"
    - 结尾给一个"今天最值得你多看一眼的事"，留判断空间给用户
    - 禁止"建议关注"这类无信息表述
    """,
)
prompt += f"\n<changes>\n{delta_block}\n</changes>"
```

**效果**：AI 解读从"每天重头分析的模板"变成"讲今天不一样的事的叙事"，信息增量高，机械感低。

### 3.4 P1 —— 参考卡：把硬信号做成"今日值得关注的"（弱化指令色彩）

**注意**：用户明确"不可能越俎代庖买卖"。所以这里不是"行动指令卡"，而是"参考卡"——把 `judge()` 已算出的硬信号 + 语境，整理成"今天值得你多看一眼的几件事"。

设计样例（参考而非指令）：

```
┌─────────────────────────────────────┐
│ 🔍 今日值得多看一眼（2026-08-25 收盘）│
├─────────────────────────────────────┤
│ ◆ 美股偏离 -1.7% → 触发加倍定投区间  │
│   趋势右侧企稳（3只），雷达无同步信号│
│   冷却期：上次 8/22，今天满 3 天可考虑│
│   → 如果你本周要定投，美股是当前偏离│
│     最大的方向，但纳指期货盘前微跌， │
│     可观察开盘再定 │
├─────────────────────────────────────┤
│ ◆ 港股偏离 +6.2% → 原信号止盈       │
│   长底仓锁定不卖，自然稀释中         │
│   → 港股消费今日领跌板块（-1.8%），  │
│     偏离可能本周自然收窄，暂不动     │
├─────────────────────────────────────┤
│ ◆ A股红利低波 雷达🟡关注             │
│   10日跌5.3%，右侧企稳确认中         │
│   → 还在左侧，等企稳信号再纳入候选   │
└─────────────────────────────────────┘
```

**与"行动卡"的区别**：
- 措辞是"如果你要定投，美股是当前方向"而非"建议买美股 ¥200"
- 每条都讲"为什么"和"但也要注意"，留判断空间
- 数据全部来自 `strategy.judge()` 已有字段（signal / deviation / trend / cooldown_status / radar_hits / timing_msg），**零新数据源**

### 3.5 P2 —— AI 解读注入硬信号（消除矛盾解读）

**问题**：当前 AI 解读 prompt 没有 `judge()` 的硬信号约束，LLM 可能在建议"关注美股机会"的同时，strategy 算出"美股已超配+冷却期未过"——两者矛盾。

**改进**：把 `judge()` 的硬信号作为 `<hard_signals>` 注入 prompt，让 LLM 在硬信号约束下生成参考：

```python
# briefing.py _ai_insight 改造（伪代码）
from src.strategy import judge
verdict = judge(pf, client)  # 已有

hard_signals_block = "\n".join(
    f"- {s['asset_class']}: {s['signal_label']} 偏离{s['deviation_pct']} "
    f"趋势:{s.get('timing','无')} 冷却:{s.get('cooldown_status','通过')}"
    for s in verdict['signals']
)

prompt += f"\n<hard_signals>\n{hard_signals_block}\n</hard_signals>"
# extra_rules 加：硬信号是 Python 死算的事实，你的解读必须与之不矛盾
```

**效果**：AI 解读不再和硬信号打架，用户看到的参考是内部一致的。

### 3.6 P2 —— 风控维度补全（让参考更立体）

## 五、一句话结论

**用户要的不是"自动买卖的决策助手"，而是"更智能的参考"**。AI 解读可用性下降的根因是代金券只覆盖 9B、前两层付费欠费中断（改降级链即可修）。但更深层的价值瓶颈是"太机械"——7 时段固定铺陈、AI 解读模板化、硬信号语境被拍平。**修复降级链是恢复 baseline；让简报"变化感知 + 叙事化解读 + 参考卡"才是把"机械参考"升级为"智能参考"的真正跃迁**——用户每条收到的都是有增量的、讲今天不一样的事的、留判断空间的参考，而不是每天一样的全量铺陈。
