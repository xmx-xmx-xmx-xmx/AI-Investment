# 全组合收益归因体检

用户问"今年没赚到钱是行情还是我的策略"时，**不要凭印象答，也不要只看持仓收益率**。必须区分三个层次：

| 层次 | 含义 | 数据来源 |
|---|---|---|
| **标的涨了多少** | 这只基金本身今年表现 | 天天基金净值序列（逐只算） |
| **你拿到多少** | 你的持有收益率 | 底仓表「最新收益率」 |
| **差额** | = 买入时点的成本 | 前两者相减 |

**"标的涨了 60%、你只拿到 0%"这种组合，问题一定在时点，不在选品。** 这是本方法最有价值的输出。

## 一、数据源与取数

### 1. 飞书「AI投资数据库」
- `BT=$(grep -E '^FEISHU_BITABLE_TOKEN=' .env | cut -d= -f2)`（从 `.env` 读取，勿硬编码）
- 底仓表 `tblpiht8ex94bM6x`｜交易流水 `tblbnD3uaEdohjji`｜雷达 `tbloKn9F9TPf4wwO`｜板块轮动 `tblsR4WDQySkxiYP`｜简报快照 `tblxJqf6BT5GfhGh`
- 导出命令：`lark-cli base +record-list --base-token $BT --table-id <id> --format ndjson --output ./data/x.ndjson --overwrite --as user`
- **底仓表关键字段**：市值 / 成本均价 / 持仓份额 / 最新收益率 / 标的代码 / 标的名称 / 标签 / 资产大类 / 投资载体 / 价格更新日期
- **交易表关键字段**：交易时间 / 交易金额 / 产品名称 / 状态 / 确认份额 / 确认净值 / 买卖方向 / 转入标的

### 2. 标的最新涨幅：天天基金净值序列（核心工具）
```bash
# 必须 HTTPS + 带 UA；HTTP 返回空文件
curl -sS --max-time 15 "https://fund.eastmoney.com/pingzhongdata/{code}.js" \
  -H "User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)" -o x.js
```
从返回的 JS 里正则抓 `Data_netWorthTrend = [...]`（数组元素 `{x: 毫秒时间戳, y: 净值}`），按日期排序：
- **基准 = 日期 ≤ 上年末（如 2025-12-31）的最后一条**（即上年末净值）
- **最新 = 数组最后一条**
- `今年以来 = 最新/基准 − 1`

26–30 只基金全部拉一遍约 1–2 分钟，注意 `time.sleep(0.15)` 限速。**缓存到 `data/nav/<code>.js`，重跑不再请求。**

### 3. 无该接口的标的
- **港股上市个股**（如 1810 小米集团-W）：用「港股行情指标」类查询，字段是"年初基准价 + 年初至今涨跌幅"
- **港股上市 ETF**（如 03486 易方达亚洲半导体、03121 南方东英KOSPI200）：无净值序列，**用底仓表的持有收益率替代**并在报告中标注
- **A股指数**：沪深300 / 上证 / 深证成指 / 万得全A / 恒生 / 恒生科技 直接搜"年初至今涨跌幅"

## 二、四个必须避开的坑（都踩过）

1. **交易表历史老记录 `买卖方向` 字段多数字段为空**（09-17 前 88 条为 `[]`）。**不能严格按 `=='buy'` 过滤**，否则历史统计全部归零。正确做法：`'sell' in dirs` 才算卖出，`'convert' in dirs` 为转换，**其余历史空值按买入处理**。
2. **交易表的时间覆盖可能远短于底仓表持有期**。交易表自 2026-06-17 起记录，而底仓表里有更早买入的债券基金。**先查时间范围，再决定能不能用它推"全年投入"。** 不能。
3. **底仓表可能漏记或存在表外动作**。**必须做一次"交易表产品名称集合 vs 底仓表标的名称集合"的差集检查**，把缺口单独列出并请用户确认。
4. **底仓表代码列曾有错**（如「…(QDII)E」曾填成 017091，应为 019118）。**按名称匹配比按代码匹配安全**；两者的差集也要报给用户。

## 三、分析口径：两个口径必须分开算

### 口径 A：持有期盈亏（表内直接可得）
`成本 = 市值 / (1 + 最新收益率)`，`持有盈亏 = 市值 − 成本`
→ 回答"我一共赚了多少"。**注意：这是自买入以来的累计，不是今年。**

### 口径 B：今年以来（YTD）——需要判断每笔的持有起始
- **上年末及以前买入、全年持有**（如固收底仓）：
  `YTD 盈亏 = 市值 × YTD / (1 + YTD)`
- **年内买入**（持有期即年内）：
  `YTD 盈亏 ≈ 持有盈亏`
- 两者相加 = 组合 YTD 盈亏

**判断依据**：若某只的「持有收益率」≈ 它的「标的 YTD」，说明大致从年初就持有；若持有收益率 << 标的 YTD，说明是年中买入（买在涨过之后）。

### 口径 C：静态权重法（回答"我的方向选对了吗"）
`组合 YTD ≈ Σ(市值 × 标的 YTD) / 总市值`
→ **这个数字与口径 B 的差距就是"买入时点"的成本**。

## 四、三段拆解框架（回答"行情还是策略"）

### 第 1 段：行情——是不是普跌？
列出主要指数 YTD。**若宽基只跌 2%–3% 而用户亏 2%，行情就不是元凶**，要找结构。
**务必单独看板块极值**：极端分化市里，"选错方向"的伤害远大于"市场下跌"。

### 第 2 段：配置——结构是否锁死了上限？
算权益占比。`即使权益赚 20%，组合也只有 权益占比 × 20%`。
**结论句式**：不是判断错，是仓位结构决定了拿不到权益收益。**并明确"低风险偏好是选择，不是错误"，只要求用户接受对应回报区间。**

### 第 3 段：节奏——建仓是否集中在高点？
按月份统计投入金额与占比；对照**宽基指数年内最高点的日期**。
再对每只算「买入时该基金大致处于什么 YTD 位置」（用成本反推），做成表。

### 责任排序表（输出核心）
| 排名 | 原因 | 类型 | 估算影响 |
|---:|---|---|---:|
| 1 | 最大亏损方向的敞口 | 配置 | −X 元 |
| 2 | 集中建仓在阶段高点 | 节奏 | −Y 元 |
| 3 | 固收占比过高 | 配置 | 机会成本 |
| 4 | 行情分化 | 市场 | 放大器 |

## 五、反事实检验（比任何说理都有力）

至少做两条：
1. **"如果最大亏损桶换成固收"** → 组合会是多少？
2. **"如果这几只在年初就持有"** → 多赚多少？

## 六、必做的两条"反直觉"检验

不要只输出坏消息。**主动找用户做对了什么**：

1. **选品能力检验**：把持仓里 YTD 涨幅最高的几只列出来。若多只在全市场头部，**说明用户选品不差**。
2. **"标的表现 vs 持有表现"排序**：找出唯一"抓住"的那只（如长期分批小额定投的宽基/纳指）。
   → **规律句式**：「持有一年以上的赚了 X%，今年集中买入的几乎全在水下。你缺的不是选品能力，是买得早和拿得住。」

**这一条是用户最需要听到的**——它把"我是不是很蠢"变成"我有一个具体可改的习惯"。

---

## 七、输出规范

1. **先给三句话结论**，再展开。
2. **数据缺口必须在第一节就列出**（缺哪些、影响多大、请用户确认什么），不要藏在末尾。
3. 每个数字标口径（持有期 / 今年以来 / 静态权重 / 标的），**绝不混用**。
4. 估算值标明精度（如"方向可信，精度约 ±0.5 个百分点"）。
5. 改进建议按**性价比排序**，且必须可执行（"盯住港股敞口"而非"注意风险"）。
6. **明确区分"你的认知"与"实际结构"**——这类认知与事实的错位是最高价值的发现。
7. 结尾固定声明：公开信息整理与组合结构分析，**不构成投资建议**。
8. 产出落盘为 `全组合收益归因_YYYY-MM-DD.md`，放在工作区根目录。
9. **收敛规则（强制）**：当用户问的是**"我的组合合理吗 / 我该做什么"**，而不是"为什么"，输出必须是：
   - ① **一个明确判断**，用「合格 / 警告 / 不合格」这类二元语言，禁止"总体上比较分散但存在优化空间"式的和稀泥；
   - ② **不超过 3 条动作**，按优先级排序，每条必须能在 10 分钟内动手或明确说"不用急"；
   - ③ **1 张图**，不叠加多张；
   - ④ 不再引入新的分析维度。若还有未展开的发现，压到最后一段"其他（可选）"。
   - 反面教材：连续给出费率表 + FIFO 拆解 + 情景推演 + 额度时间线，用户看得懂每个结论但不知道先做哪个 → 这是**信息密度过高导致的决策瘫痪**。

### 组合结构「六维记分卡」（可直接复用）

回答"组合合理吗"的固定框架，每维给合格/警告/不合格：

| 维度 | 判定标准 |
|---|---|
| 大类骨架 | 是否有打底 + 卫星 + 对冲的结构，且与风险偏好一致 |
| 打底部分 | 低波动资产是否贡献正收益、是否被频繁交易 |
| 权益分散度 | 用「只数 vs 实际方向数」比值；单一方向 > 50% 权益为不合格 |
| 重复持有 | 是否存在同一指数/同一批前十大重仓的多只基金 |
| 宽基覆盖 | 真正的宽基（非行业主题）占总资产比重，< 3% 为不合格 |
| 成本效率 | 主动管理费 vs 指数费率，及主动部分是否跑赢其基准 |

**配合的核心可视化**：把「N 只持仓」按**实际底层**归堆成少数几个方向，用水平条形图 + 金额 + 占权益比。这张图本身就能替代大段文字论证。

## 八、本组合结构性特征速查（供复盘对照）

- **底仓表覆盖范围**：只含**场外基金 + 场内 ETF**，**不含场外个股账户**。因此不可用交易表历史单反推场外股票持仓。
- **高风险跨大类重叠组**：易方达亚洲半导体 03486 + 建信新兴市场（同持台积电/三星/SK海力士）+ 南方东英KOSPI200，表面分散在"港股/美股"两个大类，底层实为同一亚洲半导体链。
- **29 条持仓 = 13 个底层主题**（A/C/E 是费率外壳，不是分散）；赚钱的主要是被动宽基（纳指/标普），亏钱的主要是港股与高点集中买入的单一行业主动主题。
- **目标权重真源**：见 `src/constants.py` 的 `TARGET_WEIGHTS`（固收45 / 美股30 / A股5 / 港股10 / 避险10）与 `docs/ACTION_RULES.md`。
